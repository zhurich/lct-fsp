## Повторный запуск

Из корня проекта в Windows PowerShell:

```powershell
backend\.venv\Scripts\python.exe -X utf8 docs/qa-2026-10-06/audit.py
backend\.venv\Scripts\python.exe -X utf8 docs/qa-2026-10-06/extended.py
backend\.venv\Scripts\python.exe -X utf8 docs/qa-2026-10-06/security_checks.py
backend\.venv\Scripts\python.exe -X utf8 docs/qa-2026-10-06/content_checks.py
```

Полный повтор существующего набора тестов:

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest -p no:cacheprovider -q --tb=short
```

Полный повтор заявленной командой синтетической валидации (пара минут):

```powershell
cd backend
.\.venv\Scripts\python.exe -X utf8 -m scripts.validate --n 2000 --seed 1 --out ../docs/qa-2026-10-06/validation-rerun.md
```

Изолированное демо для ручного UI-прогона запускается из корня отдельной командой `backend\.venv\Scripts\python.exe docs/qa-2026-10-06/serve_ui.py`, затем открывается `http://127.0.0.1:8110`. При первом старте создаёт синтетическую базу `ui.db` в этой папке, подключает готовую статическую сборку `frontend/dist`, загружает демонстрационные данные и **не читает `dev.db`**. Учётные записи и пароль описаны в корневом README. После повторной генерации интерфейса соберите frontend заново.

Для осознанного чистого повторного запуска через терминал удалять данные приложения не нужно. Если требуется повторить регистрацию и проверки, каждый запускаемый аудит создаёт отдельную временную `audit-*.db`.

## Интерпретация

Отчёт фиксирует дефекты, которые воспроизводятся на локальном стеке и синтетических данных. Статус `P0–P3` означает практический приоритет исправления, не автоматически классификацию уязвимости. Идентификатор ФСП пока проверялся на документированном мок-реестре: подмену реального внешнего ФСП API этот прогон не доказывает и не опровергает.
